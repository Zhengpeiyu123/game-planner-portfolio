# 《土豆幸存者》｜设计案例

用一个小体量原型，检查规则之间的相互影响。

- 项目形态：肉鸽小游戏原型
- 个人范围：独立完成原型
- 设计内容：武器 / 数值 / UI
- 制作方式：AI 协同 · Vibe Coding

个人职责：独立完成画面、武器、数值和 UI 原型，使用 AI 工具协同制作；通过调整参数与界面，探索快速原型的验证方式。

## 设计命题

一个参数改动，究竟改变了玩家的哪一种选择？

射程决定接敌距离，奖励与价格决定购买空间，金币吸附决定移动负担。原型提供了把这些变量放在同一体验中观察的机会，也让我能够从“数值变了”进一步追问“玩家行为是否改变”。

项目边界：这是独立快速原型，覆盖画面、武器、数值与 UI。以下参数来自保存的制作记录；设计解释为复盘分析，未提供留存、平衡性或用户测试效果数据。

## 体验结构

1. 移动与战斗：在敌人压力下选择站位和攻击距离。
2. 结束与获取：收集金币，获得每波通关奖励。
3. 购买与成长：把收益变成升级，再面对下一波。

## 设计取舍

原始记录保留了参数变化。以下将这些变化转译为复盘思考与待验证假设，不追认未记录的实验过程。

### 基础射程与升级幅度需要一起看

目标：让初始站位有压力，同时让射程升级值得选择。

方案：制作记录中，初始手枪射程从 420 调整到 190，升级射程加成从 +8% 调整到 +22%。这两项适合放在一起讨论基础能力与成长收益。

取舍：缩短射程可能增加接敌风险；加大升级幅度也可能挤压其他选项，需要在同一敌人和波次条件下比较。

验证：下一轮固定敌人、波次和其他武器参数，对照记录接敌距离、受伤位置及升级前后的有效攻击窗口。

### 经济节奏决定波间是否有真实选择

目标：让玩家在每波结束后形成有意义的购买决策。

方案：制作记录包含商品价格约降低 30%、波次涨价减半，以及每波奖励调整为“6 + 波数 × 2”。这些变量共同改变预算与可购买项。

取舍：提升购买空间可能改善成长感，也可能使难度过早被压平；奖励、价格和敌人压力需要联动检查。

验证：记录各波预算、可购买项数量、实际购买与剩余金币，检查是否存在长期无选项或固定最优选择。

### 把注意力留给战场上的判断

目标：控制拾取负担与界面遮挡，让信息服务战斗。

方案：金币吸附速度从 320 到 620、吸附范围从 60 到 80；顶栏调整为 58px 的细长半透明信息区。

取舍：更容易拾取会减少路线成本，但也会改变冒险取钱的价值；更紧凑的顶栏则需要检查小屏可读性。

验证：对照记录为拾取而偏离路线的次数，并在不同屏幕尺寸下检查生命、波次与金币是否容易读取。

## 执行规格

以下变化直接来自现有制作截图。量纲未在材料中标明的参数保留原数值，不额外解释为像素、米或每秒。

- 初始手枪射程：420 → 190：观察接敌压力与安全距离。
- 升级射程加成：+8% → +22%：检查射程成长的选择价值。
- 商店经济：商品约降价 30%；波次涨价减半。：和奖励一起检查波间购买空间。
- 通关奖励：6 + 波数 × 2：确认波数起点、发奖时点与重复结算。
- 金币吸附：速度 320 → 620；范围 60 → 80。：观察拾取负担与移动路线。
- 战斗信息栏：58px 细长半透明顶栏。：平衡信息可读性与战场遮挡。

## 交付关注点

- 数值：记录量纲、默认值、公式、叠加方式和修改原因。
- 反馈：升级前后数值、价格变化与获得奖励有清楚提示。
- 边界：核对发奖时点、重复结算、暂停与重新开始状态。
- 验证：控制其他变量，记录行为变化后再判断参数效果。

## 复盘与下一步

### 从画面到规则的完整原型

独立组织画面、武器、数值与 UI，使用 AI 工具协同完成制作。原型承担验证载体的作用，帮助暴露变量之间的关系。

### 一次修改太多变量，会模糊判断

现有记录同时包含射程、经济、拾取和界面变化。后续应保留版本基线，按问题拆开验证，才能更清楚地知道某种体验变化由什么造成。

### 用对照记录支撑下一次调整

固定波次与敌人条件，记录受伤、击杀、预算和升级选择；针对拾取与界面另做观察，避免用“感觉更好”替代可讨论的依据。
